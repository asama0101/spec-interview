# 中断したセッションを再開できるようにする SPEC

## 概要

grill-form は、質問・回答・HTML を OS の一時フォルダに置き、3 日で消す。途中で中断すると、続きから始める手段がない。

セッションを `${CLAUDE_PLUGIN_DATA}` に移し、起動時に未完了のセッションを一覧して、再開か新規かを選べるようにする。これで `plugin-rules.md` の A1（状態は `${CLAUDE_PLUGIN_DATA}` に置く）と A2（変数は引数で渡す）も満たす。

### 入力

- 利用者の依頼: 「中断したセッションを、あとで再開したい」。
- `~/.claude/reference/plugin-rules.md` の点検（2026-11-07）で、A1・A2 が現状と合わないと分かった。
- 参照するコード: `plugins/grill-form/scripts/grill_form.py`、`plugins/grill-form/skills/grill-form/SKILL.md`、`README.md`、`docs/development.md`。

## 目的と非目標

目的:
- 中断したセッションを、あとで続きから再開できる。
- SPEC を保存したら、そのセッションを片付ける（今と同じ）。
- 放置されたセッションは、14 日後に自動で消える。

非目標:
- 再開用の別コマンドは作らない。再開は `/grill-form:grill-form` の起動時に選ぶ。
- 同じテーマで起動したときの自動再開はしない。
- 進捗を持つ専用のファイルは作らない。再開時は、セッション内のファイルから Claude が判断する。
- 旧い一時フォルダ（OS の一時フォルダの `grill-form/`）の中身は、移行しない。そのまま放置する。
- 未完了セッションを手動で削除するコマンドは作らない。

## 流れ

1. 利用者が `/grill-form:grill-form` を起動する。
2. Claude が `list --data "${CLAUDE_PLUGIN_DATA}"` を実行する。このとき、14 日より古いセッションを先に削除する。
3. 未完了のセッションがなければ、新規で始める（今の手順 1 へ）。
4. あれば、選択肢で聞く。「新規」と、セッションごとの「再開（テーマ・更新日時・最新のファイル名）」を出す。
5. 「新規」なら `init --data "${CLAUDE_PLUGIN_DATA}" --theme …` で作り、今の手順 1 以降を行う。
6. 「再開」なら、そのセッションのフォルダ内のファイルを読み、どこまで進んだかを判断して、続きの手順から始める。
7. SPEC を保存したあと、`cleanup --data … --session-dir … --spec … --yes` でセッションを削除する（今と同じ）。

## 仕様

### 置き場所

- セッションは `${CLAUDE_PLUGIN_DATA}/sessions/<日時>_<テーマ>_<乱数>/` に置く。名前の形式は今のものを引き継ぐ。
- `init` が、セッションのフォルダに `session.json`（`{"theme": "<テーマ>", "created": "<ISO 8601>"}`）を書く。
- `--plugin-dir` で動かしたときは、`${CLAUDE_PLUGIN_DATA}` が本番と別になる。本番のセッションは見えない。

### サブコマンドの変更

| サブコマンド | 変更 |
| --- | --- |
| `init` | `--data` を必須にする。置き場所を `<data>/sessions/` にする。古いセッションの削除は、ここでは行わない（`list` で行う） |
| `list` | 新設。`--data` を必須にする。14 日より古いセッションを削除してから、残りを 1 行ずつ出す。形式は `<フォルダ名>`・`<テーマ>`・`<更新日時>`・`<最新のファイル名>` をタブ区切り。更新日時の新しい順 |
| `cleanup` | `--data` を必須にする。削除してよいのは `<data>/sessions/` の直下のフォルダだけ。それ以外は今のとおり何もしない |
| `render`・`spec-path`・`doctor` | 変更なし（`--data` を取らない） |

- 「古い」の基準と一覧の更新日時は、セッションのフォルダ内で最も新しいファイルの更新日時とする（フォルダ自体の mtime は、既存ファイルの上書きで変わらないため使わない）。ファイルがなければ、フォルダの mtime を使う。
- `session.json` がない・読めないフォルダは、テーマを `(不明)` にして一覧に出す。14 日より古ければ、ほかと同じく削除する。
- テーマとファイル名に含まれるタブ・改行は、空白に置き換えて出す。ファイルがまだないセッションの最新のファイル名は `(なし)` と出す。
- `list` は、削除した件数を出さない。出力の形式を変えないため。同時に動いている別のセッションの作業中のフォルダを削除する可能性は、14 日の基準では実害が小さいので許容する。
- `--data` が空文字のときは、`init`・`list`・`cleanup` はエラーで終わる。
- `cleanup` は、`resolve()` したあとの親が `<data>/sessions` と一致するかで判定する。Windows に合わせ、大文字小文字は区別しない。
- 中止（HTML の「中止」ボタン）したセッションも、未完了として一覧に出る。14 日で消える。

### SKILL.md の変更

- 冒頭に「未完了セッションの確認」の手順を足す（流れの 2〜6）。
- 再開時に続きを決める基準を、ファイルの状態ごとの表で書く。表の行は次のとおり。テーマは `session.json` のものを使い、SPEC の保存先は `spec-path --theme` で決める。
  | セッション内の状態 | 続き |
  | --- | --- |
  | `intake.html` だけ（`intake.answers.md` なし） | 入力フォームを開き直して、送信を待つ（手順 2） |
  | `intake.answers.md` あり、`round-0.*` なし | 回答を読み、事前確認（手順 3）から |
  | `round-N.html` あり、`round-N.answers.md` なし（N は最大） | その HTML を開き直して、送信を待つ（手順 6〜7） |
  | `round-N.answers.md` あり、次の `round-(N+1).html` なし（N は最大） | 回答を読んで design tree を更新し、次のラウンドへ（手順 8） |
  | `final-K.html` あり、`final-K.answers.md` なし（K は最大） | その HTML を開き直して、送信を待つ（手順 9） |
  | `final-K.answers.md` が `承認` | SPEC を保存して片付ける（手順 10） |
  | `final-K.answers.md` が `修正あり` | コメントを反映し、K を 1 増やして手順 9 を繰り返す |
  | 上のどれにも当てはまらない | 状態をユーザーに見せて、続け方を聞く |
- 質問 ID は通しで一意なので、再開時は、既存の `round-*.json` の最大の ID の次から付ける。
- `init`・`cleanup` の呼び出しに `--data "${CLAUDE_PLUGIN_DATA}"` を付ける。
- 「3 日」の記述を「14 日」に直す。中止したときの報告は、「セッションが残っていて、再開できる。14 日後に自動で削除される」とする。
- `allowed-tools` に `list *` を足す（`python` と `python3` の両方）。

### README・docs の変更

- README の「残るもの」から、「中断したものは 3 日後に消える」「専用の保存場所を作らない」を直す。未完了セッションは `${CLAUDE_PLUGIN_DATA}` に 14 日残ることと、アンインストールで消えるか（実装時に確認し、実際の動きを書く）を書く。
- 使い方に、再開の流れを追加する。
- `docs/development.md` のサブコマンド表と保存先の表を直す。

## 受入条件

1. `init --data D --theme T` が `D/sessions/` の下にフォルダを作り、`session.json` を書く。
2. `list --data D` が、未完了のセッションを更新日時の新しい順に、タブ区切りで出す。セッションがなければ何も出さず、終了コード 0 で終わる。
3. `list` が、14 日より古いセッションを削除する。13 日前のものは残る。
4. `cleanup` が、`D/sessions/` の直下のフォルダだけを削除する。`D/sessions/` の外のフォルダは削除せず、終了コード 1 で終わる。SPEC がなければ何も削除しない（今と同じ）。
5. `--data` を付けないと、`init`・`list`・`cleanup` は使い方のエラーで終わる。
6. 空白・日本語を含む `--data` のパスで、`init`・`list`・`cleanup` が動く。
7. SKILL.md に、起動時に `list` を実行し、選択肢で「新規」か「再開」を聞く手順と、ファイルの状態ごとの再開の表がある。`allowed-tools` に `list *` がある。
8. 既存のテスト、`ruff check`、`ruff format --check`、`claude plugin validate --strict`（直下とプラグイン側）が通る。
9. SKILL.md・README・`docs/development.md` に、「3 日」と一時フォルダの記述が残っていない。

## リスク

- 再開時の進捗の判断は、Claude がファイルを読んで行う。判断を誤ると、同じ質問を繰り返したり、答え済みの質問を飛ばしたりする。進捗の専用ファイルを持たないので、判断の手がかりはファイル名（`round-N.html`・`round-N.answers.md`・`final-K.*`）だけになる。
- `${CLAUDE_PLUGIN_DATA}` が、アンインストールや更新で消える可能性がある。消える場合、未完了のセッションも一緒に消える。
- 秘密情報を含む回答が、14 日間 `${CLAUDE_PLUGIN_DATA}` に残る。OS の一時フォルダより長く残る。README に注意を書く。
- 旧い一時フォルダに残るセッションは、誰も削除しない。OS の掃除に任せる。
