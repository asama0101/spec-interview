# grill-form

計画や設計を、ブラウザのフォームに答えながら詰めて、SPEC（仕様書）の 1 ファイルにまとめる Claude Code 用のプラグインです。Windows 11 専用です。

## 機能

Claude の質問に、ターミナルではなくブラウザのフォームで答えます。決めることがなくなるまで質問が続き、最後に承認すると SPEC ができます。

| できること | 内容 |
| --- | --- |
| フォームで答える | 候補を選ぶ、コメントを書く、あとで決める、聞き返す、のどれかで答えます |
| 推奨案を見る | 各質問に、Claude の推奨案と理由が付きます |
| 資料を渡す | 依頼文と参考資料を、作業フォルダのツリーから選びます。PDF・Word・PowerPoint・Excel・Markdown・テキストを、元の場所のまま読みます |
| 中断して再開する | 途中でやめたセッションを、あとから続けられます |
| SPEC を 1 ファイルで受け取る | 概要・流れ・受入条件・非目標・リスク・決定ログをまとめた Markdown が 1 つできます。ほかのプラグインや別のセッションに、そのまま渡せます |

## 前提条件

| 必要なもの | 内容 |
| --- | --- |
| OS | Windows 11。macOS と Linux は対象外です |
| Claude Code | [Claude Code](https://docs.claude.com/en/docs/claude-code) |
| Python | 3.8 以上。標準ライブラリだけで動くので、追加のライブラリは要りません |
| Node.js | Playwright MCP を `npx` で起動するために使います。`/grill-form:doctor` は確認しません |
| Playwright MCP | ローカルの HTML を開き、送信を検知するために使います。このプラグインには同梱していないので、導入方法の手順 3 で登録します |
| ブラウザ | Chrome か Edge を推奨します |

## 導入方法

手順 1 から 4 を、順に行います。

### 1. マーケットプレイスを追加する

Claude Code で実行します。

```
/plugin marketplace add asama0101/grill-form
```

GitHub を使わず、手元にコピーして入れるときは、次のようにします。

```bash
git clone https://github.com/asama0101/grill-form.git <任意のフォルダ>/grill-form
```

```
/plugin marketplace add <任意のフォルダ>/grill-form
```

### 2. プラグインを入れる

```
/plugin install grill-form@grill-form
```

- 更新は `/plugin` の画面から行います。手元にコピーしたときは、先にそのフォルダで `git pull` します。
- 反映には Claude Code の再起動が必要です。手順 3 のあとに、まとめて 1 回行います。

### 3. Playwright MCP を登録する

Git Bash で実行します。

```bash
claude mcp add playwright --scope user -- npx @playwright/mcp@latest --allow-unrestricted-file-access --output-dir "$(python -c 'import tempfile; print(tempfile.gettempdir())')/playwright-mcp"
```

| 引数 | 役割 |
| --- | --- |
| `--allow-unrestricted-file-access` | `file://` の HTML を開くために必要です |
| `--output-dir` | Playwright MCP の記録の置き場所です。指定しないと作業フォルダに `.playwright-mcp/` ができるので、OS の一時フォルダ配下にします。上のコマンドが、一時フォルダの場所を Python で調べて埋めます |

- ブラウザを指定するときは、`--browser chrome` または `--browser msedge` を足します。
- すでに `playwright` を登録していると、上書きされません。[困ったとき](#困ったとき)の手順で登録し直してください。

登録したら、Claude Code を再起動します（手順 2 の反映も、ここで済みます）。`claude mcp list` に `playwright` が出れば成功です。

### 4. 動作環境を確認する

Claude Code の中で実行します。何も変更しません。

```
/grill-form:doctor
```

結果は Claude が日本語で知らせます。ターミナルから直接確認するときは、手元にコピーしたリポジトリの直下で次を実行します。

```bash
python plugins/grill-form/scripts/grill_form.py doctor
```

確認する項目は、次の 4 つです。

| 項目 | 内容 |
| --- | --- |
| Python | 3.8 以上である |
| `claude` コマンド | PATH にある |
| Playwright MCP の登録 | `playwright` の名前で登録されていて、30 秒以内に応答する |
| `file://` の許可 | 登録に `--allow-unrestricted-file-access` が付いている |

そろっていれば `OK: 動作に必要なものはそろっています。` と出ます。足りないものがあると `NG: …` と理由を出し、終了コード 1 で終わります。`NG:` のあとの文言と同じ見出しを、[困ったとき](#困ったとき)で探してください。

## 使い方

### コマンド

Claude Code で使えるコマンドは、次の 2 つです。

| コマンド | 内容 |
| --- | --- |
| `/grill-form:grill-form [テーマ]` | フォームで質問に答えて、SPEC を作ります。未完了のセッションがあれば、再開もできます |
| `/grill-form:doctor` | 動作に必要なものがそろっているか確認します。何も変更しません |

### 最初の 1 回

Claude Code で、作業フォルダを開いて、次のように頼みます。

```
/grill-form:grill-form API の認証方式を詰めたい
```

ブラウザに入力フォームが開きます。依頼文と参考資料を渡して「送信」を押すと、Claude が自動で検知して次へ進みます。ターミナルへの入力は要りません。「grill して」だけでは起動しません。`/grill-form:grill-form` を呼ぶか、「grill-form で〜」「HTML で grilling」と書いたときだけ使われます。

### 進み方

承認するまで、次の 4 つの段階が順に進みます。

| 段階 | 内容 |
| --- | --- |
| 1. 入力フォーム | 依頼文と参考資料を渡します |
| 2. 事前確認 | 目的とゴール、障壁、制約を確認します。Claude が推奨案を埋めるので、確認と修正だけです |
| 3. 質問ラウンド | 決めることがなくなるまで、質問のフォームを繰り返します。終わる前に、保留や曖昧な回答が残っていないかを点検し、残っていれば質問に戻ります |
| 4. 最終確認 | SPEC 案が出ます。「承認」で SPEC が保存され、Claude がそのパスを知らせます。「修正あり」を選ぶと、コメントを反映した案がまた出ます |

- 最終確認の SPEC 案は、出す前に、観点の違う 5 つのレビュアーが確かめます。
- 途中でやめるときは、どのフォームでも「中止」を 2 回押します。SPEC は作られません。

### 中断したセッションを再開する

同じ作業フォルダで、もう一度 `/grill-form:grill-form` を実行します。未完了のセッションがあると、「新規」と「再開」の選択肢が出ます。別のフォルダで始めたセッションは出ません。

```
/grill-form:grill-form
```

- 「再開」には、テーマ・更新日時・最新のファイル名が付きます。選ぶと、Claude がセッションのファイルを読み、続きのフォームから始めます。
- 「新規」を選ぶと、中断したセッションは残したまま、新しく始めます。
- 中止したセッションも、一覧に出ます。
- 14 日より古いセッションは、起動時に自動で削除されます。

### 入力フォーム

| 欄 | 内容 |
| --- | --- |
| 依頼文 | 「テキスト」か「ファイル」のどちらかで渡します。テキストは、何を詰めたいか、背景、分かっている制約の自由記述です。ファイルは、作業フォルダの中から 1 つ選びます |
| 参考資料 | 左のフォルダをクリックすると、右に資料が出ます。チェックで選び、別のフォルダへ移ってもチェックは残ります。Shift を押しながらクリックすると、前にクリックしたファイルから範囲でまとめて選べます |
| フォルダを読み直す | 作業フォルダにファイルを足したときに押します。入力した内容とチェックは残ったまま、フォームが開き直されます |

- 作業フォルダは、Claude Code を起動したフォルダです。
- 作業フォルダの外のファイルやフォルダは、各欄の下のパス欄に書きます。参考資料は 1 行に 1 つです。パス欄に書くと、ツリーの選択より優先されます。
- 依頼文と参考資料は、どちらか 1 つだけでも構いません。
- 一覧に出るのは、docx・pdf・pptx・xlsx・md・txt です。作業フォルダの 3 階層目までを調べ、隠しファイル、`.git`、`node_modules`、`__pycache__`、リンクは出しません。1 つのフォルダに 200 件、全体で 5,000 件を超えると、一部だけ表示されます。そのときは、パス欄を使ってください。
- 資料は、Claude が元の場所から読みます。コピーしません。PDF・Word・PowerPoint・Excel は、Claude の pdf・docx・pptx・xlsx スキルで読みます。
- PDF の図形は、ページを画像として読みます。PowerPoint と Excel は文字と図形の構造だけを読むので、図形が重要なときは PDF に書き出して渡してください。

### 質問への答え方

- 画面の上に、質問の一覧が出ます。一覧の印は、次の意味です。質問の番号を押すと、その質問へ移ります。いま答えている質問は、色の付いた枠と札で示されます。

  | 印 | 意味 |
  | --- | --- |
  | ● | 回答済み |
  | △ | 保留 |
  | ? | 要確認 |
  | ○ | 未回答 |

- 未回答の質問が残っていると、1 回目の「送信」で警告が出ます。このまま送るときは、もう一度「送信」を押します。
- 候補をクリックして選びます。候補の左の文字（`A`・`B`・`C`…）は、回答に使う記号です。
- 1 つだけ選ぶ質問は、マウスで選ぶと、次の質問へ移ります。矢印キーで動かしただけでは移りません。複数選べる質問は移りません。
- 緑の札「推奨」の候補が、Claude の推奨案です。理由は候補の下に出ます。
- 「コメント」を押すとコメント欄が開きます。候補を選んだときは、理由や条件の補足になります。候補を選ばずに書いたコメントは、それ自体が回答です。候補にない答えは、こちらに書いてください。
- 今決められないときは「あとで決める」、意味が分からないときは「聞き返す」を押します。聞き返しは次のラウンドで、Claude が説明か補足質問を返します。聞き返しが残っている間は、質問は終わりません。
- 選んだ候補を取り消して、コメントだけで答えるときは、「選択をクリア」を押します。

### 残るもの

承認すると、次の 1 ファイルだけが残ります。

```
<作業フォルダ>/docs/grill-form/specs/<日付>-<テーマ>-design.md
```

- 例: `docs/grill-form/specs/2026-11-03-api-design-design.md`。フォルダがなければ作ります。同じテーマを同じ日に 2 回承認すると、末尾に連番（`-2`、`-3`）が付きます。既存のファイルは上書きしません。
- 先頭に `status: 未対応` が書かれます。実装計画が保存されると `完了` に変わり、`plan:` に計画のパスが入ります。更新の手順は、SPEC の末尾の「後続の手順」に書かれています。
- 実装計画の置き場は `docs/grill-form/plans/` です。計画づくりは、別のスキル（superpowers の writing-plans など）で行います。計画の実装が終わったら、計画の `status:` を `完了` にします。
- 概要の「入力」に、依頼文の要約と、渡した資料の元のパスが入ります。
- 依頼文の原文、質問と回答の履歴、入力ファイルは残りません。資料はコピーしないので、元のファイルを動かすと辿れなくなります。
- SPEC は、そのまま git の管理対象になります。機密を書いたときは、`.gitignore` に `docs/grill-form/` を加えてください。

### 作業中のファイルと削除

作業中のファイル（質問・回答・HTML）は、プラグインのデータフォルダ（`${CLAUDE_PLUGIN_DATA}`）の `sessions/` に置かれ、承認すると消えます。中断したセッションは、再開しなければ 14 日後に消えます。

- 注意: 回答に秘密情報を書いたときは、中断したセッションに最大 14 日残ります。気になるときは、再開して承認するか、`sessions/` の中の該当フォルダを自分で削除してください。
- 警告: アンインストールすると、プラグインのデータフォルダ（`~/.claude/plugins/data/<プラグイン ID>/`）は既定で削除され、中断したセッションも消えます。消えたセッションは戻せません。残すときは、`claude plugin uninstall grill-form@grill-form --keep-data` を実行します。
- アンインストールしても、SPEC と Playwright MCP の登録は残ります。Playwright MCP はほかのツールと共有するので、不要なときだけ `claude mcp remove playwright` を自分で実行します。

## 設定

設定ファイルはありません。

- 使うブラウザは、導入方法の手順 3 のコマンドで決まります。変えるときは、手順 3 を参照してください。

## 困ったとき

画面や `/grill-form:doctor` に出る文言を、見出しにしています。

### NG: Python 3.8 以上が必要です。

原因: 動いた Python の版が 3.8 より古いです。

対処: Python 3.8 以上を入れて、`python --version` で版を確かめます。

### `python` コマンドが見つからない

原因: `python` が PATH にありません。この場合、`doctor` は動かないので、`NG:` は出ません。

対処: `python3` が使えるなら、`python` を `python3` に読み替えます。Claude は、自動で読み替えます。どちらもなければ、Python 3.8 以上を入れます。

### NG: claude コマンドが見つかりません

原因: `claude` コマンドが PATH にありません。Playwright MCP の確認に使います。

対処: `claude --version` が通るターミナルで、もう一度実行します。

### NG: Playwright MCP を確認できません

原因: `playwright` の名前で登録されていないか、30 秒以内に応答がありません。

対処: `claude mcp list` で `playwright` を確認します。なければ、導入方法の手順 3 で登録し、Claude Code を再起動します。あるのに応答がないときは、`claude mcp get playwright` が接続できるかを確かめます。Playwright MCP の `browser_*` ツールがないと言われたときも、同じ対処です。

### NG: Playwright MCP に --allow-unrestricted-file-access が付いていません

原因: すでに `playwright` が登録されていて、`claude mcp add` が効いていません。`file://` のページも開けません。

対処: 次の順で登録し直します。

1. `claude mcp get playwright` で、いまの引数とスコープを確認します。
2. `claude mcp remove playwright --scope <スコープ>` で削除します。
3. 元の引数を残したまま、`--allow-unrestricted-file-access` と `--output-dir` を付けて登録し直します。
4. Claude Code を再起動します。

### スキルが起動しない

「grill-form で〜」か「HTML で grilling」と書いて頼んでください。「grill して」だけでは、通常の `grilling` スキルが使われます。`/grill-form:grill-form` で直接呼ぶこともできます。入れた直後は、Claude Code を再起動し、`/plugin` で `grill-form` が有効か確認します。

### 送信が検知されない

「送信」を押したあと、「送信しました」と出ているか確認してください。約 30 分待っても送信がないと、Claude が続行方法を聞きます。フォームの「Markdown をコピー」で、回答を貼る方法もあります。

### 足したファイルが一覧に出ない

一覧は、フォームを開いた時点の作業フォルダの中身です。ファイルを足したら「フォルダを読み直す」を押してください。3 階層より深いフォルダ、隠しファイル、対応していない形式は出ません。パス欄にパスを書けば指定できます。

### ファイルのパスが読めない

存在しないパスや、フォルダのパスは読めません。Claude から、再入力を求められます。

### SPEC が想定外の場所にできた

SPEC は、Claude Code を起動したフォルダの `docs/grill-form/specs/` にできます。サブフォルダで Claude Code を起動していないか確認してください。

### セッションの削除に失敗した

シェルのカレントフォルダが、セッションのフォルダの中にないか確認してください。SPEC は保存済みです。残ったセッションは、次回の起動時に、14 日より古いものから自動で消えます。

### 日本語のテーマ名が文字化けする

テーマ名は、ASCII の短い名前（例: `api-design`）にしてください。
